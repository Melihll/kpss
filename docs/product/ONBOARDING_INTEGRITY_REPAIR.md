# Onboarding integrity repair (local, 2026-10-10)

Ordinary Today/Week/Roadmap reads no longer bootstrap P48 or generate a plan. The legacy bootstrap name now checks an existing active strategy and returns metadata without writes; a new profile gets `P48_SETUP_REQUIRED`. Self-service P48 initialization remains unsupported and is shown honestly in the UI.

Configured pilots retain their existing plans. A missing week requires a deliberate `POST /p48/week/generate` with `{ "intent": "generate_week" }`. The server validates selected P48 subjects, positive capacity and active targeted resources, then calls the existing planner through `create_p48_week_once`. That SECURITY INVOKER wrapper locks the owned active profile and returns an existing plan on duplicate/concurrent requests. It does not introduce Planner V2 authority or change Confirm/Apply/Coach gates.

Onboarding reads `weekly_availability_state(profileId)` to obtain rows and a revision together. It saves through `replace_weekly_availability(profileId, windows, expectedRevision)`. The RPC validates all windows, locks the owned draft/active profile and replaces rows within one transaction. Invalid/overlapping input or any INSERT error preserves old rows. Identical retries preserve row IDs; different concurrent changes from one revision get `AVAILABILITY_CONFLICT`. Empty windows are explicit zero capacity. A transport failure is ambiguous, so the UI asks the user to refresh and check persisted hours.

The week creation RPC independently checks owned subjects, real positive availability or explicit daily capacity, an active targeted resource for a selected subject and nonempty blocks. Existing-plan retries remain read-only even if configuration has subsequently changed. Both new migrations are additive; historical migrations and table/RLS policies are unchanged. Direct legacy table writers still exist and do not participate in the new revision/lock protocol. Coordinate older clients before any future rollout. Existing overlapping windows will require explicit user correction before this RPC accepts a replacement. Bootstrap seeding scripts must use isolated explicit fixtures; they must never reseed existing users.

Run `node scripts/run-onboarding-integrity-tests.mjs` against the existing verified local stack. It uses real signup JWTs, newly created disposable users, actual Edge/REST/RPC requests and narrowly scoped temporary database fault instrumentation removed in `finally`. No reset is used. Canonical importer tests and the roadmap smoke script use `scripts/lib/local-p48-pilot-fixture.mjs`, restricted to the exact local URL.
